How to read this

The first run was mostly about creating files. This one measures drift. All 18 public files that already existed passed every deterministic rule, but 3 of them no longer described the repo. A build pipeline, a module and a startup side effect had all changed since the file was written. Only reading the code next to the file showed it. A clean rule run means the commands and paths are real. It does not mean the file is current. As before, nothing here measures whether agents work better with these files, and every change is a PR waiting for the owner.

Results

Before and after

  • 18 files existed: 0 errors, 0 warnings, 0 infos before and after.
  • 3 were updated because the code had moved on (3 to 7 changed lines each).
  • 2 repos without a file got one (24 lines each), built from the README, design notes, CI workflow and code.
  • 2 repos were skipped on purpose: a profile README and a repo with no code. A file there would be ceremony.
  • Median AGENTS.md length: 27 lines (19–35).

What the agent did

  • For each file with commits after its last edit (7 public repos), read the diff since then and compared it with the file. 3 needed changes, and 4 had only README, link or CI churn that did not affect the file.
  • Judged every handoff item. It dropped the ones that were already specific, and tightened one line to name the test fakes it relies on.
  • Ran nothing from the repos. Every command in the new and updated files comes from package.json, the README, a workflow or a script header.

What reading the repos turned up

Instruction files drift with features, not with renames 3 repos

None of the drift was a broken path or script, which is what the rules check. It was behavior: an API that now writes prompts and datasets to an external service at startup, a rate limiter that handles IPs and has tests CI does not run, and an evaluator the file warned about but never named.

Docs that disagree with the repo 2 repos

A README that links a LICENSE file that does not exist, and a README layout that lists a module under a name the code no longer uses. Written down, not fixed, because both are outside AGENTS.md.

A known mismatch still open 1 repo

A port mismatch between a compose file and a Dockerfile, which the first run recorded in AGENTS.md, is still there. The file still warns about it, which is the right place until someone fixes it.

Findings about the tool

Each item is reproduced on a small synthetic repo, so none depends on any repository's content.

@/ path alias read as a broken import fixed in #35

An alias such as `@/lib/store` in inline code was parsed as an @ import of an absolute path. AMC005 reported it as an error. Because the file then counted as import-only, AMC009 skipped its missing-boundaries check.

Suggestion: Done: targets starting with / or ~ are no longer imports. Tests for both rules.

AMC002 silent when a file moved into a subfolder reproduced

If a file referenced as `notes.ts` moves to scripts/notes.ts, the rule stays silent because a file with that name exists below the root. That holds even when git history records the move, and even when the line says "at the root".

Suggestion: Check git renames before the "exists below" fallback, and report a move as info with the new path.

AMC009 secrets check matched by unrelated words reproduced

A file whose only match is "design token utilities" passes the "rule about secrets" check, because tokens? matches any token.

Suggestion: Require token next to a word such as access, API, auth or bearer, or only on Never / Ask-first lines.

Handoff items still dominated by boundary lines 16 of 24 items

This was reported in the first run and is unchanged. Standard Always / Ask first / Never lines make up most items, and none of them led to a change.

Suggestion: Collapse standard boundary and secrets lines into one item per file, or skip them.

No signal for "the code moved on since this file was edited" 3 stale files missed

Every stale file passed every rule and produced no handoff item about the change. The agent found them by reading git log since the file's last commit.

Suggestion: Add an advisory handoff item listing top-level paths changed since the instruction file's last commit (git is already used for ignore checks). It stays deterministic and offline, and never affects the exit code.

Method and limits

  • Fresh clones of every non-archived repo. One branch and one PR per changed repo, assigned to the owner, nothing merged.
  • Deterministic pass: --format json. Agent pass: --format agent, plus the git history since each file's last edit.
  • Run with the tool at main plus the alias fix; without it no public result changes.
  • The same agent wrote and reviewed the changes, so the review is not independent. The owner's review is the real check.
  • Public repos only. IDs are ordered by type and file length, not by name, and do not match the first report's IDs.
