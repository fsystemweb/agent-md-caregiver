How to read this

The deterministic rules can only check a file that exists. For 33 of 37 repos the baseline was a trivial 0 findings, because there was nothing to check. The real change is that they now have a short, verified file. A clean run proves the commands, paths and package manager are real. It does not prove the file makes an agent better at the repo. That is not measured here, and none of the files have had a human review yet; each one is a PR waiting for the owner.

What the agents did

  • Built every Commands section from real scripts and lockfiles, and never executed anything from the repos.
  • Added Boundaries (Always / Ask first / Never) with a secrets rule to every file.
  • Replaced vague prose rules with ones naming a concrete path or command, after reviewing the handoff items.
  • Kept the existing author rules in the 4 repos that had a file, and kept CLAUDE.md as a one-line @AGENTS.md import where it existed.

What reading the repos turned up

Committed secret material

5 of 37 repos had signing keys, tracked env files, or credentials in docs or source. AGENTS.md now marks them off-limits for agents; rotating and purging them is a human job and was not part of these PRs.

Docs that disagree with the repo

At least 8 repos had a README naming a framework version, file, script or env example that does not exist. The new files use the verified values, and AMC002 caught a stale file name on its own.

Dependencies and scripts that do not match

Missing declared dependencies, a lint script without a config, a tests folder covering one module, a shadowed module name and a port mismatch were found by reading, and were written down instead of silently worked around.

Findings about the tool

Friction the agents hit, most useful first. Each is a candidate improvement to agent-md-caregiver.

AMC006 "no commands" is too narrow 4 repos

Only a short list of tool prefixes counts. Chained commands (&&), env-prefixed commands and tools such as streamlit are missed, and content-only or static repos cannot satisfy it honestly.

Suggestion: Recognise more runners and chained commands; let a stated "no build tooling" line satisfy the rule.

Review handoff is noisy on standard Boundaries lines 119 items, several repos

Every Always/Ask first/Never line is surfaced as an unchecked instruction, and there is no way to mark one reviewed.

Suggestion: Suppress or batch the standard boundary and secrets lines; add a reviewed marker.

AMC003 false positives 2 repos

A command mentioned inside a prohibition ("never run X against production") or in a Conventions note was read as a contradiction with the Commands section.

Suggestion: Ignore mentions inside Never/Ask-first lines and non-imperative notes.

AMC002 false positives 2 repos

An inline-code package name ending in .js, and a path that lives inside a pinned CDN package, were reported as missing repo paths.

Suggestion: Skip names that match a declared dependency or sit inside a URL context.

No way to exclude vendored instruction files 1 repo

A third-party skill folder with a 2,000+ line AGENTS.md dominated one repo's results; the only option was to downgrade a rule for the whole repo.

Suggestion: Add an ignore globs option to the config.

AMC001 on undeclared test runners 1 repo

A test runner invoked through python -m but documented as installed separately is flagged. Correct, but it forces a prose workaround.

Suggestion: Offer a softer severity when the README documents the install.

No detection of committed secrets 5 of 37 repos (14%)

Rules only check that a "never commit secrets" line exists. Reading the repos found key material or credentials tracked in git, in docs or in source.

Suggestion: Out of scope for the checker, but a pointer in the report ("run a secrets scanner") would help.

Method and limits

  • Fresh clones; one branch and one PR per repo, nothing merged.
  • Deterministic pass: --format json. Agent pass: --format agent, with each handoff item judged by the writing agent.
  • The writing agent also did the review, so it is not independent. A human reviewer is the real check.
  • Repo IDs are ordered by type and size, not by name.
